# ITMO · AI Automation / Issue Desk

Проект для практик 7.1, 7.2, 8. Система: GitHub → n8n Webhooks → AI review / Issue classifier / Weekly report. Пользовательский интерфейс: React, Mantine, Vite.

## Сценарий практики 8

Пользователь вводит заголовок и описание → клиент валидирует форму → отправляет POST на локальный `/api/create-issue` → Vite proxy передаёт запрос в production webhook n8n → n8n создаёт Issue через GitHub API → клиент показывает номер и ссылку на GitHub Issue. Второй webhook GitHub автоматически запускает классификатор.

## Запуск

```bash
cd frontend
cp .env.example .env
# Впишите в .env значение N8N_URL=https://...app.n8n.cloud
npm install
npm run dev
```

Откройте http://127.0.0.1:5173.

## Тестирование

```bash
cd frontend
npm test
npm run build
```

`frontend/tests/App.test.jsx` содержит 7 тестов: вывод компонентов и пустого списка; обязательные поля; слишком короткий ввод; полный сценарий с подменой ответа API; loading и защита от дублирования; ошибка и повторная отправка; пустой ответ API. `vi.stubGlobal('fetch', ...)` подменяет сервер в тестах, но не в рабочем приложении.

## Макет и оформление

Интерактивный AI-прототип: `design/mockup.html`. В прототипе есть переключение состояний: пусто / ввод / загрузка / успех / ошибка. Использована библиотека **Mantine 7** (`Paper`, `Button`, `TextInput`, `Textarea`, `Badge`, `Alert`). Общая тема задана в `frontend/src/main.jsx`, стили — в `frontend/src/styles.css`.

## Применение AI

AI помог разработать макет, компоненты, структуру формы и клиентские тесты. После проверки вручную добавлены/уточнены: проверка ответов сервера, блокировка повторной отправки `pending.current`, видимый фокус, состояния загрузки/ошибки и проверки на задержку/повторный запрос. В n8n дополнительно проверены реальные запросы, URL AI API, credentials и условия запуска. Не указывайте, что именно вы исправили, если это не соответствует вашей работе.

## Секреты и n8n

`.env`, API-ключи, GitHub personal access tokens и credentials n8n не должны попадать в Git. Для практик 7.1/7.2 экспортируйте **текущие работающие** workflow из n8n через меню `... → Download` отдельно; старые JSON-шаблоны не отражают внесённые в n8n исправления.
